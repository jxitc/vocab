# Iter 3 Test Report

## What Improved (vs Iter 1)

- **数字终于正常了！** "17-year-old"、"1,000"、"800" 都乖乖待在文章里，不像Iter 1那样消失。我终于能读懂文章了。
- **生词从13个降到了6个**，虽然还是略多（我期望3-5个），但至少不会满屏黄让我想关掉了。
- **每个生词旁边都有发音喇叭🔊**，我不会读的词终于能听到发音了。虽然实际听不听到要手动测（见下面Audio部分），但至少图标在那，给我安全感。
- **"本课生词 (6个)"面板**把生词汇总在一起，读完可以直接复习，不用在文章里来回找。
- **关掉浏览器再打开，之前点过的词还在！** 进度保存了，不会让我白做功。Iter 1时关掉就全没了，很伤。
- **普通单词点开跳有道词典了**，不再是全英文Merriam-Webster。至少我能看懂中文。
- **没点生词就按"我读完了"，会弹出提醒**——"你还没有点击任何生词哦！"——不像Iter 1直接冷冰冰说学了0个。
- **提示文字把颜色规则说清楚了**："黄色高亮=还没学，点过了会变绿"。
- **文章内容还是科技类的**，虽然不是我100%热爱的（我更喜欢游戏/体育），但关于学生发现行星的故事至少不会让我睡着。

## What Still Frustrates Me

（按严重程度排序，从一个初中生的嘴里说出来）

### 1. 生词面板点击没反应
"本课生词"面板里我点了一下"discovery"，结果没有任何反应——弹窗没出来，词也没变绿，好像什么都没发生。我去文章里点同一个词，弹窗才出来。那这个面板的作用到底是什么？只是给我看的列表吗？如果面板里的词也能点开看释义，或者点了能跳转到文章里那个词的位置，我会更有安全感。

### 2. 6个生词还是有点多
虽然比Iter 1的13个好了太多，但我的上限是3-5个。碰到6个生词我还需要一点心理建设。考虑到discovery和discover其实是同一个词的不同形式（名词vs动词），实际重复出现的新概念大概5个左右，勉强能接受。但如果能严格控制在5个以内会更好。

### 3. "solar"的释义不够贴切
"太阳的"这个释义没错，但在这个语境里（"outside our solar system"），我看到"太阳"联想到的是"太阳"，觉得意思不通。如果显示"太阳系的"会更准确，不会让我卡住。

### 4. 第一次打开页面看到了加载过程
页面刚打开时空白了一小会儿才出现文章（客户端渲染从API取数据的过程）。Iter 1是服务端直出的HTML，一刷新马上就有内容。现在多了等待时间，虽然很短，但我这种急性子会有点不耐烦。如果有个加载动画提示"正在为你准备今天的新闻..."会好很多。

### 5. 发音喇叭太小了
图标16x16像素，我手机上可能要点不准。而且所有图标长得一模一样，我不确定点哪一个会发出哪个词的声音——是不是应该点"discovery"旁边的喇叭还是点"discovery"这个词本身？

## Critical Gaps for Iter 4

（排名分先后）

1. **面板单词应该可交互** — "本课生词"面板里的词点击后应该能做点什么：要么弹出释义、要么跳转到文章中的位置、要么标记为已学。现在它是只读列表，浪费了生词汇总的价值。

2. **need actual pronunciation testing** — 让真人用Chrome/Safari测试一下Web Speech API的实际发音质量。特别是"telescope"这种多音节词，初中生能不能听清每个音节。

3. **生词面板应该反映已学状态** — 文章里点过的词变绿了，但面板里的同一个词颜色没变。视觉上不一致。面板里的词也应该变绿/加勾，这样我一眼就能看到"我学了4个，还有2个没学"。

4. **加载状态提示** — 客户端渲染从API拉数据时加一个简单的loading spinner或骨架屏，让用户知道页面正在加载而不是卡死了。

5. **生词数量继续收敛** — 虽然discovery/discover算同一个词根，但尽量把每篇生词控制在3-5个不同词根。

6. **释义应该考虑语境** — "solar"在"outside our solar system"中应释义为"太阳系的"而非"太阳的"。给AI/词典增加上下文感知的释义生成。
